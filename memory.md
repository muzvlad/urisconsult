# memory.md — важные решения проекта urisconsult

## Архитектура
- **Один порт на весь проект — 56755.** Это HTTP-API (`bot/api_server.py`),
  который поднимает Flask в фоновом потоке из `bot/bot.py`. Telegram-бот
  порта не имеет (long polling). UI — десктопный Tkinter, HTTP-клиент без
  своего порта. БД — файл SQLite, порта не имеет.
  Порт задаётся одной константой `API_PORT` в `bot/config/__init__.py`.
- `bot/api_server.py __main__` — запуск API отдельно от бота, для отладки.
  Порт тот же (`API_PORT`), не 8080.
- UI ходит только в API. Прямого доступа к SQLite у UI нет (спека 039).

## Безопасность
- `worker_id` и `filename` из URL проверяются регулярным выражением в
  `before_request` — иначе `..` в URL уводит за пределы `DOCS_DIR`.
- Тип файла — по magic-байтам (`FileSaver.check_magic`), не по расширению.
- Авторизация API опциональна: `API_TOKEN` (env/`.env`) → `X-API-Token`.
  Без токена API открыт, бот пишет об этом предупреждение в консоль.
- `NETWORK_SERVER` (SMB-шар) недоступен → откат на локальную БД **с записью
  предупреждения в лог**.

## Данные
- Email в анкете отсутствует намеренно (спека 014) — не «восстанавливать».
- `created_at` документа: `save_documents` сохраняет дату первой загрузки,
  `replace_document` обновляет её (дата замены фиксируется намеренно,
  спека 036). Не смешивать эти два пути.
- `db.save_worker` в `ON CONFLICT` обновляет только колонки, переданные в
  `data` — частичное обновление не должно затирать остальные поля.
- Списочные выборки `db` — явный список колонок `WORKER_LIST_COLUMNS`
  (без `relatives_json`, без `email`, но с `rejection_reasons`: экспорт
  карточек в PDF печатает замечания).

## Правила проверки
- Тесты: `python -m pytest -q` из корня (255). `bot/tests` включены в
  `testpaths`.
- Перед коммитом: `python -m pytest -q` + `python -m compileall bot UI/src`.
- Линтера в проекте нет (ruff не установлен) — не выдумывать команды.
