## Ключевые решения

### Безопасность API (056)
- `worker_id`/`filename` из URL валидируются регулярным выражением в одном
  `before_request` (`bot/api_server.py`). Раньше `DELETE /api/workers/..` удалял
  каталог `bot/Users` вместе с `users.db`.
- Тип файла проверяется по magic-байтам (`FileSaver.check_magic`), а не по
  расширению. Проверка делается в двух местах: бот — сразу после загрузки
  (пользователь получает внятный отказ), API — при загрузке из UI.
- Авторизация опциональная: `API_TOKEN` в `bot/.env` → заголовок `X-API-Token`.
  Не задана — работает как раньше (README описывал «auth нет намеренно»).
- Порт API — одна константа `API_PORT` в `bot/config/__init__.py` (56755).
  Раньше порт был в трёх местах, включая мёртвый `api_server.py __main__` (8080)
  и подсказку в `setup.bat` (8080).

### Целостность анкеты (058)
- Потеря данных при «Исправить анкету»: `handle_rejected_callback` копировал
  11 полей, `DBSaver.save_worker_data` писал для остальных `''` — и
  `registration`, семейное положение и родственники стирались. Лечится
  копированием всех полей в FSM.
- «Новая анкета» больше НЕ вызывает `db.resubmit_worker`: старая запись
  остаётся отклонённой (история), новая создаётся отдельно. Иначе в «ожидании»
  висели две анкеты — старая (без документов) и новая.
- `save_documents` сохраняет `created_at` первой загрузки (спека 051), но
  `replace_document` НЕ трогаем — там дата замены фиксируется намеренно
  (спека 036, тест `test_replace_document_overwrites_file_and_keeps_record`).

### Ложные находки аудита
- «email теряется» — не баг: email намеренно убран из анкеты (архивная спека
  014, `personal_keys` в `db.save_worker`).
- «multi_file + fix-режим сломан» — не баг: `_skip_document` уже корректно
  переводит на следующее отклонённое поле.

### UI (059)
- `~F.text` (aiogram magic filter) — фильтр «сообщение не текст».
  Регистрация текстовых хендлеров с `F.text` + один общий `expect_text`
  для текстовых состояний (через `StateFilter`).
- `save_worker` в `ON CONFLICT` обновляет только колонки, переданные в `data`.
- Списочные выборки `db` — явный список колонок `WORKER_LIST_COLUMNS`:
  без `relatives_json` и `email`, но С `rejection_reasons` (нужен экспорту
  карточек в PDF).
- `bot/tests` добавлены в `testpaths` pyproject — теперь `python -m pytest -q`
  запускает всё (253).

## Что осознанно НЕ сделано

- Сеть в главном потоке Tk (карточка работника, скачивание файлов) — большой
  рефакторинг с риском для UI; вместо этого починены колокольчик (один поток)
  и инвалидация кэша после перезаливки.
- `TelegramService.send_rejection` оставлен: он только пишет в лог (уведомление
  отправляет фоновая задача бота), но покрыт тестами.
- Авторизация API не сделана обязательной — это сломает развёртывание, пока
  `API_TOKEN` не задан в `.env` на сервере и в UI.
