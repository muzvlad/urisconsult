# 12.11.2026 — Вшивка API-токена в UI-EXE (спека 061)

## Что сделано
- `UI/build_exe.py`: при сборке токен берётся из `UI_BUILD_API_TOKEN` → `API_TOKEN`
  (переменные окружения) → `API_TOKEN=` в `bot/.env` и вшивается в бандл EXE
  через сгенерированный `UI/src/_api_secret.py`.
- Сгенерированный файл удаляется сразу после сборки (`finally`), значение токена
  в лог сборки не выводится. `UI/src/_api_secret.py` в `.gitignore`.
- `UI/src/config.py`: приоритет токена — env var > `.env` рядом с EXE > вшитый
  в EXE > пусто. Чтение `.env` снимает кавычки и BOM (иначе значение в EXE и
  на сервере различалось бы на символ и UI получал 401).
- Тесты: 272 (было 255). Новые `UI/tests/test_api_token.py` (11),
  `UI/tests/test_build_exe.py` (6).

## Проверка
- Полная сборка EXE (PyInstaller 6.22, Python 3.14): токен найден в PYZ как
  `src._api_secret`, в константах модуля — значение токена.
- Запуск собранного EXE против mock-сервера: запросы уходят с заголовком
  `X-API-Token` и встроенным значением, без `.env` и без `API_TOKEN` в
  окружении.
- `python -m pytest -q` — 272 passed.

## Ключевые решения
- Токен в EXE извлекаем — это ключ уровня сотрудника кадров. Обфускация не
  делается: она не добавляет защиты и создаёт ложное ощущение.
- Секретность обеспечивается закрытым портом 56755, а не бинарником.
- Ротация токена: сменили на сервере → старые EXE получают 401. Переопределить
  без пересборки можно `.env` рядом с EXE или переменной окружения
  `API_TOKEN` — они имеют приоритет над вшитым.
- Токен на машине сборки берётся из `bot/.env` — этот файл в git не попадает,
  утечки в репозиторий нет.
