# Telegram-бот URIS Consult

## Описание

Telegram-бот для пошагового сбора данных сотрудников. Ведёт анкету через FSM (Finite State Machine), загружает документы, сохраняет всё в SQLite.

## Запуск

```bash
cd bot
pip install -r requirements.txt
echo BOT_TOKEN=ваш_токен > .env
python bot.py
```

## Диалог с ботом

### 1. Регистрация

Бот запрашивает по порядку:

| Шаг | Поле | Тип ввода |
|---|---|---|
| 1 | ФИО | Текст |
| 2 | Гражданство | Кнопки: Патент / Студент / ЕАЭС / РВП / ВНЖ / Россия |
| 3 | Пол | Кнопки: Мужской / Женский |
| 4 | Дата рождения | Текст ДД.ММ.ГГГГ (валидация) |
| 5 | Менеджер | Текст |
| 6 | Объект | Текст |
| 7 | Адрес объекта | Текст |
| 8 | Должность | Текст |
| 9 | Основной телефон | Текст (валидация) |
| 10 | Доп. телефон | Текст (опционально) |

> ФИО, менеджер и родственники автоматически приводятся к формату «Первая буква заглавная, остальные строчные» (включая части после дефиса), независимо от того, как клиент ввёл текст.

### 2. Загрузка документов

Документы зависят от категории гражданства:

**Патент (26 документов):**
Фото → Паспорт → Перевод паспорта → Миграционная карта → Регистрация (лицевая) / скрин Амина → Регистрация (оборотная) → Дактилоскопия (лицевая) → Дактилоскопия (разворот) → ДМС → Патент (лицевая) → Патент (разворот) → Чек 1 … Чек 11 → Сертификат языка → ИНН → СНИЛС → Реквизиты карты

**Студент (10 документов):**
Фото → Паспорт → СНИЛС → Регистрация → Миграционная карта → ДМС → ИНН → Дактилоскопическая карта → Справка из ВУЗа → Реквизиты карты

**ЕАЭС (13 документов):**
Фото → Паспорт / идентификационная карта (лицевая) → ID-карта (разворот) → Перевод паспорта → Миграционная карта → Регистрация (лицевая) / скрин Амина → Регистрация (оборотная) → Дактилоскопия (лицевая) → Дактилоскопия (разворот) → Полис ДМС или ОМС → ИНН → СНИЛС → Реквизиты карты

**РВП (7 документов):**
Фото → Паспорт → Миграционная карта → ДМС/ОМС → ИНН → СНИЛС → Реквизиты карты

**ВНЖ (9 документов):**
Фото → Паспорт → Миграционная карта → ВНЖ → ДМС/ОМС → ИНН → СНИЛС → Трудовая книжка → Реквизиты карты

**Россия (8 документов):**
Фото → Паспорт → Паспорт прописка → ИНН → СНИЛС → Документ об образовании → Трудовая книжка → Военный билет

Каждый документ можно пропустить (кнопка «Пропустить»).

### 3. Подтверждение

Экран с полной сводкой данных. Кнопки:
- **Подтвердить** — сохранение в БД
- **Редактировать** — выбор поля для исправления (из конфига)
- **Заполнить заново** — начало заново

### 4. Обработка анкет

Администратор в UI может:
- **Принять** → статус `accepted`
- **Отклонить** → выбор полей → уведомление клиенту в Telegram
- Клиент исправляет через `/start` → статус возвращается в `pending`

## Хранение данных

### База данных

Путь: `bot/Users/users.db` (SQLite, WAL mode)

Схема определена в `shared/__init__.py` (общий модуль для бота и UI).

Таблица `workers`:

| Группа | Колонки |
|---|---|
| Основное | id, name, citizenship, gender, position, object, object_address, manager |
| Контакты | phone_main, phone_additional, email, date |
| Семья | marital_status, relatives_json |
| Мета | registration, telegram_id, telegram_username, created_at, updated_at |
| Статус | status (pending/accepted/rejected), rejection_reasons, notified_at |

Таблица `worker_documents` (UNIQUE по worker_id + doc_type):

| Колонка | Описание |
|---|---|
| worker_id | FK → workers.id |
| doc_type | Ключ документа из DOC_FLOWS |
| filename | Имя файла в bot/Users/docs/ |

Таблица `worker_meetings`:

| Колонка | Описание |
|---|---|
| worker_id | FK → workers.id |
| date | Дата встречи |
| note | Заметка |

### Версионирование схемы

БД использует `PRAGMA user_version` для отслеживания версии. Миграции выполняются **один раз** при обновлении версии.

Текущая версия: **2**

| Версия | Описание |
|---|---|
| 0 | Старая схема (колонки документов в workers) |
| 1 | Нормализованная схема (worker_documents) |
| 2 | Добавлены status, rejection_reasons, notified_at |

### Файлы документов

Папка: `bot/Users/docs/`

Структура: `bot/Users/docs/{worker_id}/{prefix}.{ext}`

Префиксы определены в `config/documents.py` → `DOC_PREFIXES`.

## Валидация

| Поле | Правило |
|---|---|
| ФИО | Минимум 2 слова, только буквы, пробелы, дефис |
| Телефон | Минимум 10 цифр (любые символы автоматически фильтруются) |
| Email | Формат name@domain.com |
| Дата рождения | Формат ДД.ММ.ГГГГ, реальная проверка через datetime |

## Архитектура

### Динамический FSM

Состояния FSM генерируются автоматически из `config/documents.py`:
- Добавление нового типа документа требует правки **только** в `documents.py`
- FSM создаётся лениво через `get_worker_form()`

### Утилиты (`utils.py`)

- `get_document_state(doc_key)` — получение FSM-состояния для документа
- `build_edit_keyboard(citizenship)` — генерация клавиатуры редактирования из конфига
- `get_all_doc_keys()` — все ключи документов
- `get_field_prompt(field)` — текст запроса для поля
- `validate_file_extension(file_path)` — единая валидация расширений

### Логирование

- Context vars: `worker_id`, `user_id` в каждом лог-записи
- Формат: `%(asctime)s [%(levelname)s] %(name)s [uid=%(user_id)s w=%(worker_id)s]: %(message)s`

## Технические детали

- **FSM**: aiogram 3.x SQLiteStorage (выживает при перезапуске бота)
- **БД**: aiosqlite (async), WAL mode, `busy_timeout=10000`
- **Клавиатуры**: Reply (действия) + Inline (гражданство, редактирование)
- **Токен**: файл `.env` → `BOT_TOKEN`
- **Сетевой сервер**: файл `.env` → `NETWORK_SERVER`
- **Rate limiting**: 5 сообщений / 10 сек, фоновая очистка
- **Тесты**: 106 тестов (config, db, handlers)
