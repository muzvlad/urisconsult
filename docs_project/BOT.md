# Telegram-бот URIS Consult

## Описание

Telegram-бот для пошагового сбора анкет сотрудников. Работает на FSM aiogram,
сохраняет данные и документы в SQLite и параллельно поднимает Flask API для
десктопного приложения.

## Запуск

```bash
cd bot
pip install -r requirements.txt
echo BOT_TOKEN=ваш_токен > .env
python bot.py
```

При старте бот:

1. Создаёт папки `Users/` и `Users/docs/`.
2. Инициализирует БД и выполняет миграции.
3. Запускает API-сервер на `0.0.0.0:56755` в фоновом потоке.
4. Запускает polling Telegram и фоновые задачи.

## Диалог с ботом

### 1. Регистрация

| Шаг | Поле | Тип ввода |
|---|---|---|
| 1 | ФИО | Текст |
| 2 | Гражданство | Кнопки: Патент / Студент / ЕАЭС / РВП / ВНЖ / Россия |
| 3 | Пол | Кнопки: Мужской / Женский |
| 4 | Дата рождения | Текст `ДД.ММ.ГГГГ` |
| 5 | Менеджер | Текст |
| 6 | Объект | Текст |
| 7 | Заказчик | Текст |
| 8 | Адрес объекта | Текст |
| 9 | Должность | Текст |
| 10 | Основной телефон | Текст, обязателен |
| 11 | Доп. телефон | Текст или «Пропустить» |

Email больше не запрашивается. Колонка `workers.email` оставлена для старых
записей.

ФИО, менеджер и родственники приводятся к виду «первая буква заглавная,
остальные строчные», включая части после дефиса.

### 2. Документы

Состав и порядок документов заданы в `bot/config/documents.py` (`DOC_FLOWS`).
Потоки:

**Патент (16):**
Паспорт → Перевод паспорта → Миграционная карта → Регистрация (лицевая) /
скрин Амина → Регистрация (оборотная) → Дактилоскопия (лицевая) →
Дактилоскопия (разворот) → ДМС → Патент (лицевая) → Патент (разворот) →
Чек 1 → Чек 11 → Сертификат о знании языка → ИНН → СНИЛС → Реквизиты карты

**Студент (14):**
Фото → Паспорт → Перевод паспорта → Виза → Миграционная карта →
Регистрация (лицевая) → Регистрация (оборотная) → Дактилоскопия (лицевая) →
Дактилоскопия (разворот) → ДМС → СНИЛС → ИНН → Справка из ВУЗа →
Реквизиты карты

**ЕАЭС (13):**
Фото → Паспорт / ID-карта (лицевая) → ID-карта (разворот) →
Перевод паспорта → Миграционная карта → Регистрация (лицевая) →
Регистрация (оборотная) → Дактилоскопия (лицевая) →
Дактилоскопия (разворот) → ДМС или ОМС → ИНН → СНИЛС → Реквизиты карты

**РВП (9):**
Фото → Паспорт → Паспорт (разворот с РВП) → Паспорт (разворот с пропиской) →
Миграционная карта → ДМС/ОМС → ИНН → СНИЛС → Реквизиты карты

**ВНЖ (10):**
Фото → Паспорт → Миграционная карта → ВНЖ → Регистрация → ДМС/ОМС → ИНН →
СНИЛС → Трудовая книжка/ЭТК → Реквизиты карты

**Россия (9):**
Фото → Паспорт → Паспорт прописка → ИНН → СНИЛС → Документ об образовании →
Трудовая книжка/ЭТК → Военный билет → Реквизиты карты

Для каждого документа есть кнопка «Пропустить». Документы с `multi_file`
(трудовая книжка, военный билет) принимают несколько файлов; «Пропустить»
завершает загрузку этого типа.

После документов для категории «Россия» бот запрашивает семейное положение и
родственников. Для остальных категорий сразу открывается подтверждение.

### 3. Подтверждение

Экран с полной сводкой. Доступны:

- «Подтвердить» — сохранить анкету
- «Редактировать» — выбрать поле или документ и исправить
- «Заполнить заново» — начать заново

### 4. Обработка анкет

Администратор работает через UI:

- Принять → `accepted`
- Отклонить → выбрать поля и комментарии → уведомление клиенту в Telegram
- Клиент исправляет через `/start` → статус снова `pending`

Фоновая задача проверяет отклонённые анкеты каждые 60 секунд и отправляет
уведомления.

## API-сервер

`bot/api_server.py` — Flask-приложение, запускается из `bot/bot.py` на порту
`56755` (`threaded=True`).

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/workers` | Список с фильтрами `status`, `search`, `archived`, `date_from`, `date_to` |
| GET | `/api/workers/<id>` | Карточка |
| PUT | `/api/workers/<id>` | Обновление полей |
| DELETE | `/api/workers/<id>` | Удаление записи и файлов |
| PUT | `/api/workers/<id>/accept` | Принять |
| PUT | `/api/workers/<id>/reject` | Отклонить с причинами |
| PUT | `/api/workers/<id>/resubmit` | Вернуть в pending |
| POST | `/api/workers/<id>/archive` | В архив |
| POST | `/api/workers/<id>/unarchive` | Из архива |
| PUT | `/api/workers/<id>/legal-entity` | Сохранить юр. лицо |
| PUT | `/api/workers/<id>/hr-status` | Сохранить HR-статус |
| GET | `/api/pending/count` | Количество новых |
| GET | `/api/workers/<id>/documents` | Список документов |
| POST | `/api/workers/<id>/documents` | Загрузка/замена документа |
| GET | `/docs/<worker_id>/<filename>` | Выдача файла |
| GET | `/api/workers/<id>/meetings` | Встречи |
| POST | `/api/workers/<id>/meetings` | Добавить встречу |
| GET | `/api/workers/<id>/notes` | Комментарии |
| POST | `/api/workers/<id>/notes` | Добавить комментарий |
| PUT | `/api/workers/<id>/notes/<note_id>` | Изменить комментарий |
| DELETE | `/api/workers/<id>/notes/<note_id>` | Удалить комментарий |

Ограничения:

- `archived` принимает `0`, `1`, `all`
- `date_from` и `date_to` — ISO-даты
- HR-статус проверяется по списку; для `employed` и `fired` обязательна дата
- API не имеет авторизации и слушает все интерфейсы; не публикуйте порт наружу

## Хранение данных

### База данных

Путь: `bot/Users/users.db` (SQLite, WAL mode). Если в `.env` задан доступный
`NETWORK_SERVER`, используется `<NETWORK_SERVER>/bot/Users/users.db`.

Схема определена в `shared/__init__.py`.

Таблица `workers`:

| Группа | Колонки |
|---|---|
| Основное | id, name, citizenship, gender, position, object, customer, object_address, manager |
| Контакты | phone_main, phone_additional, email (legacy), date |
| Семья | marital_status, relatives_json |
| Мета | registration, telegram_id, telegram_username, created_at, updated_at |
| Статус бота | status, rejection_reasons, notified_at |
| UI | legal_entity, hr_status, hr_status_date, archived_at |

Таблица `worker_documents`:

| Колонка | Описание |
|---|---|
| worker_id | FK → workers.id |
| doc_type | Ключ из `DOC_FLOWS` |
| filename | Имя файла в папке сотрудника |
| created_at | Дата загрузки |

`UNIQUE(worker_id, doc_type)` снят: у одного типа может быть несколько файлов.

Таблица `worker_meetings`:

| Колонка | Описание |
|---|---|
| worker_id | FK → workers.id |
| date | Дата и время встречи |
| note | Примечание |
| created_at | Дата создания |
| notified_at | Когда отправлено уведомление |
| reminded_at | Когда отправлено напоминание |

Таблица `worker_notes`:

| Колонка | Описание |
|---|---|
| worker_id | FK → workers.id |
| text | Текст комментария |
| created_at, updated_at | Даты |

### Версионирование схемы

Используется `PRAGMA user_version`. Текущая версия: **7**.

| Версия | Изменение |
|---|---|
| 0 | Документы хранились в `workers` |
| 1 | Нормализованная `worker_documents` |
| 2 | `status`, `rejection_reasons`, `notified_at` |
| 3 | `updated_at` |
| 4 | Снят `UNIQUE(worker_id, doc_type)` |
| 5 | Заполнены пустые даты создания и изменения |
| 6 | Заказчик, юр. лицо, HR-статус, архив, уведомления встреч, комментарии |
| 7 | Добавлен `documents_signed` |

### Файлы документов

Папка: `bot/Users/docs/{worker_id}/`

Имя файла: `{prefix}{ext}` для первого файла и `{prefix}_{index}{ext}` для
последующих. Префиксы заданы в `DOC_PREFIXES`.

Примеры: `pas.jpg`, `reg.jpg`, `chek1.pdf`, `trud.pdf`, `trud_2.pdf`.

## Уведомления

- **Отклонение** — бот отправляет замечания клиенту (проверка раз в 60 секунд).
- **Новая встреча** — уведомление сразу после добавления.
- **Напоминание** — за 24 часа до встречи.
- Встречи архивных анкет и анкет без `telegram_id` не отправляются.
- Проверка встреч выполняется каждые 30 секунд.

## Валидация

| Поле | Правило |
|---|---|
| ФИО | Минимум 2 слова, буквы, пробелы и дефис; нормализация регистра |
| Телефон | Минимум 10 цифр, остальные символы отбрасываются |
| Дата рождения | `ДД.ММ.ГГГГ`, проверка через `datetime` |
| Файл | Расширения jpg, jpeg, png, bmp, gif, pdf; до 20 МБ |

## Архитектура

### Динамический FSM

Состояния и клавиатуры строятся из `config/documents.py`. Новый тип документа
добавляется в одном файле; форма создаётся лениво через `get_worker_form()`.

### Утилиты

- `get_document_state(doc_key)` — FSM-состояние документа
- `build_edit_keyboard(citizenship)` — клавиатура редактирования
- `get_field_prompt(field)` — текст запроса поля
- `validate_file_extension(path)` — проверка расширения
- `parse_meeting_datetime(value)` — разбор даты встречи
- `parse_rejection_reasons(value)` — нормализация причин отклонения

### Логирование

- Contextvars `worker_id` и `user_id` в каждой записи
- Формат: `%(asctime)s [%(levelname)s] %(name)s [uid=%(user_id)s w=%(worker_id)s]: %(message)s`
- Файл: `bot/logs/bot.log`

## Технические детали

- FSM: aiogram 3.x `SQLiteStorage` (состояние выживает при перезапуске)
- БД: aiosqlite, WAL, `busy_timeout=30000`, `foreign_keys=ON`
- Rate limiting: 5 сообщений / 10 секунд (фото и документы не учитываются)
- API: Flask, порт 56755 (`API_PORT`), фоновый поток
- Зависимости: aiogram, aiohttp, aiosqlite, Flask, python-dotenv, pydantic, Pillow
- Тесты: 219 в `docs_project/tests` и `bot/tests`

## Конфигурация

Файл `bot/.env`:

```
BOT_TOKEN=ваш_токен_бота
NETWORK_SERVER=
API_SERVER=http://127.0.0.1:56755
API_TOKEN=
API_PORT=56755
```

- `NETWORK_SERVER` — путь к сетевой папке; если пуст или недоступен,
  используется `bot/Users/` (пишется предупреждение в лог)
- `API_SERVER` — адрес API для UI; также можно задать переменной окружения
- `API_TOKEN` — токен доступа к API; UI отправляет его в `X-API-Token`.
  Пусто — API без авторизации
- `API_PORT` — порт API-сервера, по умолчанию `56755`
