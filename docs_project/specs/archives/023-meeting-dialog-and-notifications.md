# Спека 023 — Окно встречи и уведомления

## Проблема

1. Окно «Добавить встречу» размером 400x260 (`UI/src/dialogs.py:439`) слишком
   маленькое: поле примечания — одна узкая строка, текст плохо виден.
2. Уведомления о назначенной встрече не отправляются вообще. В боте есть только
   фоновая задача по отклонённым анкетам (`bot/bot.py:157`).

## Решение

### Окно встречи

- `MeetingDialog` увеличить до 520x430.
- Поле примечания: `tk.Text` height 6, width 50, `wrap=tk.WORD`.
- Дата и время — отдельные поля, шрифт крупнее, подсказка формата.
- Валидация:
  - дата строго `дд.мм.гггг` и реальная дата;
  - время строго `чч:мм` (00–23, 00–59);
  - ошибка показывается в `messagebox`, окно не закрывается.
- Хранить дату встречи как `дд.мм.гггг чч:мм` — в этом же виде показывать в карточке
  и PDF. Старые значения ISO парсить отдельным хелпером.

### Уведомления

- Миграция v6 добавляет `worker_meetings.notified_at`, `reminded_at`.
- `bot/services/db.py`:
  - выбрать встречи без `notified_at` вместе с `workers.telegram_id`, `name`,
    `object`, `archived_at`;
  - выбрать встречи для напоминания: `notified_at` заполнен, `reminded_at` пуст;
  - `mark_meeting_notified(meeting_id, value)`, `mark_meeting_reminded(meeting_id, value)`.
- `bot/utils.py`: `parse_meeting_datetime(value)` поддерживает
  `дд.мм.гггг чч:мм`, `дд.мм.гггг` и ISO `YYYY-MM-DD HH:MM:SS`.
- `bot/bot.py`: новая фоновая задача `check_meeting_notifications(bot)` раз в 30 секунд.
  - Сразу после создания встречи: сообщение работнику.
  - За 24 часа до встречи: напоминание. Если встреча создана менее чем за 24 часа,
    напоминание не дублируется — при мгновенной отправке сразу заполняется `reminded_at`.
  - Архивные анкеты пропускаются.
  - Нет `telegram_id` — встреча помечается обработанной, чтобы не было вечного цикла.
  - Ошибка отправки — `notified_at` остаётся пустым, будет повторная попытка.
  - Некорректная дата — лог и пометка обработанной, чтобы не зациклиться.
- Запуск задачи в `bot.main()` рядом с `check_rejected_workers()`, отмена при остановке.
- `bot/api_server.py`: `POST /api/workers/<id>/meetings` дополнительно проверяет
  непустую дату и формат; возвращает `{"ok": true, "id": ...}`.

Сообщение при создании:

```
Вам назначена встреча
ФИО: ...
Дата и время: дд.мм.гггг чч:мм
Примечание: ...
```

Напоминание:

```
Напоминание о встрече через 24 часа
ФИО: ...
Дата и время: дд.мм.гггг чч:мм
```

## Критерии приёмки

1. В окне встречи читаемо видно многострочное примечание.
2. Неверная дата/время не сохраняются.
3. Работник получает сообщение сразу после создания встречи.
4. Работник получает напоминание за 24 часа, без дублей.
5. Старые встречи после миграции не рассылаются.
6. Архивные анкеты не получают уведомлений.

## Тесты

- `docs_project/tests/test_meeting_notifications.py`:

  - выбор только неотправленных встреч;
  - пропуск архивных и без `telegram_id`;

  - отсутствие повторной отправки.
- `docs_project/tests/test_db.py`: колонки встреч после миграции; backfill старых записей.

## Риски

- Уведомление появляется с задержкой до 30 секунд из-за polling — это допустимо.
- При недоступном Telegram попытки повторяются каждые 30 секунд; в лог пишется warning.
