# Спека 005 — Бот молчит при исправлении анкеты после отклонения по документу

## Проблема

После отклонения анкеты в UI с причиной «ИНН» (или любым другим **документом**) бот при нажатии
«Исправить анкету» отправляет только:

> Начинаем исправление анкеты.
> Будет предложено исправить только отклонённые поля.

…и молчит: не запрашивает файл, не переходит к следующему полю. При повторном `/start` и нажатии
«Исправить анкету» — тот же результат. Текстовые поля при этом исправляются нормально.

## Причина

`bot/handlers/commands.py` в функции `_ask_rejected_field` (строки 293–313) для документа вызывает
`get_skip_keyboard()`:

```python
await message.answer(f"Отправьте исправленный файл: {doc_label}",
                     reply_markup=get_skip_keyboard())
```

Но `get_skip_keyboard` **не импортирован** в `commands.py` (импорт есть только в `documents.py:17`
и `registration.py:16`). Ветка документа в `_ask_rejected_field` падает с `NameError` сразу после
сообщения «Начинаем исправление анкеты…». Обработчик callback выбрасывает исключение, aiogram
молча логирует его, пользователь ничего не получает.

ИНН — документ `patent_inn` (ключ в `all_doc_keys`), поэтому симптом воспроизводится именно при
отклонении по документу. Ранее «Регистрация» была текстовым полем и попадала в другую ветку — после
коммита `2136d53` (отклонение по регистрации идёт как документ) документная ветка стала основным
путём и баг всплыл.

## Решение

### 1. Импорт `get_skip_keyboard` в `bot/handlers/commands.py`

Добавить:

```python
from keyboards.reply_kb import get_skip_keyboard
```

Это минимальный фикс — функция уже используется в файле, остальной код документной ветки корректен.

### 2. Проверка: тесты

Тестов на `_ask_rejected_field` сейчас нет (поиск по `docs_project/tests` — пусто). Ошибка была
обнаружена вживую. Добавить тест, который вызывает `_ask_rejected_field` с ключом документа и
проверяет, что запрашивается файл (не падает с `NameError`). Тест без реального Telegram-API —
через мок `message.answer` и `state.set_state`.

## Критерии приёмки

1. После отклонения по документу (например, ИНН) бот запрашивает «Отправьте исправленный файл: …»
   с клавиатурой «Пропустить».
2. После приёма файла бот переходит к следующему отклонённому полю или к подтверждению.
3. Текстовые поля исправляются как раньше.
4. Новый тест зелёный; весь прогон `pytest docs_project/tests/` зелёный.
