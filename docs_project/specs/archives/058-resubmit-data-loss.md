# Спецификация 058 — не терять данные анкеты при исправлении и не плодить дубли

## Проблема
- `bot/handlers/commands.py:55-60` при исправлении отклонённой анкеты копирует в FSM только 11 полей. Поля `registration`, семейное положение (`marital_status`) и родственники (`relatives_json`) не переносятся → `DBSaver.save_worker_data` пишет для них пустые значения, и при сохранении исправленной анкеты данные стираются безвозвратно.
- Кнопка «Новая анкета» (`new_rejected:`) вызывает `db.resubmit_worker(worker_id)` — отклонённая запись становится `pending`, и клиент затем создаёт ещё одну запись. В списке «в ожидании» оказываются две анкеты: старая (с прежними данными, без документов) и новая.
- `POST /api/workers/<id>/documents` без `old_filename` сохраняет файл на диск, но не создаёт запись в `worker_documents` — документ не виден в UI и теряется при перезагрузке.
- `db.save_documents` удаляет записи по `doc_type` и вставляет заново — при перезагрузке того же файла `created_at` (дата первой загрузки) сбрасывается (спека 051).

## Что изменить
- `handle_rejected_callback` переносит в FSM все личные поля: `registration`, `marital_status` → `russia_marital_status`, `relatives_json` → `russia_relatives_list` (JSON разбирается в список).
- `new_rejected:` больше не переводит отклонённую запись в `pending` — она остаётся отклонённой (история), новая анкета создаётся как отдельная запись. Дубликатов в «ожидании» не остаётся.
- В API после сохранения нового файла создаётся запись `worker_documents` (`db.add_document`), если её ещё нет.
- `db.save_documents` запоминает `created_at` существующей записи с тем же именем и переиспользует его вместо даты перезагрузки. `replace_document` не трогаем — там дата замены фиксируется намеренно (спека 036).

## Критерий приемки
Исправление анкеты сохраняет `registration`, семейное положение и родственников; после «Новая анкета» в статусе pending не больше одной записи клиента; загруженный из UI документ появляется в карточке; `created_at` документа не меняется при повторной загрузке того же файла.

## ponytail
Без новых таблиц: переиспользование существующих `worker_documents` и `handle_rejected_callback`.
