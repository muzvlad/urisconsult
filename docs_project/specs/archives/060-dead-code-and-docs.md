# Спецификация 060 — убрать мёртвый код и привести документацию в порядок

## Проблема
- `UI/src/services.py`: `PDFExportService.export_list` (~150 строк) и `_count_pdf_items` не вызываются ни из UI, ни из тестов; `TelegramService.send_rejection` только пишет в лог (уведомление отправляет фоновая задача бота), но держит отдельный пул потоков и API, который выглядит как рабочий.
- `UI/src/services.py:_draw_worker_card` вычисляет `doc_path` (сетевой запрос файла) и нигде его не использует — лишний HTTP-запрос на каждую карточку в PDF.
- `UI/src/dialogs.py`: `RejectDialog` объявлен как `List[str]`, фактически передаётся `List[Dict[str, str]]`.
- Документация устарела: `docs_project/README.md`, `BOT.md`, `UI.md` описывают схему БД версии 6, «21 маршрут API», «147 тестов» и не упоминают `API_TOKEN`, `API_PORT` и `X-API-Token`.

## Что изменить
- Удалить неиспользуемые `PDFExportService.export_list`, `_count_pdf_items` и неиспользуемый вызов `doc_path`.
- Тип `RejectDialog` привести к фактическому (`List[Dict[str, str]]`).
- Обновить документацию: версия схемы БД, число маршрутов и тестов, переменные `API_PORT`/`API_TOKEN`, заголовок `X-API-Token`, единый порт 56755.

## Критерий приемки
В `UI/src` не остаётся неиспользуемых методов экспорта; PDF-карточка не делает лишний запрос файла документа; документация соответствует коду (схема 7, порт 56755, `API_TOKEN`).

## ponytail
Удаление вместо нового кода; документация — правка существующих файлов, без новых.
