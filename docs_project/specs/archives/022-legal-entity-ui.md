# Спека 022 — Поле «Юр. лицо» в UI

## Проблема

В карточке нет юридического лица, и пользователь UI не может внести его вручную.
Бот это поле не собирает и не должен.

## Решение

Свободный текст, доступный только в UI. Поле не участвует в отклонении анкеты:
бот не знает этот ключ и не сможет корректно запросить исправление.

### БД и API

- Колонка `workers.legal_entity TEXT` уже добавляется миграцией v6 (спека 021).
- `bot/services/db.py`: `set_legal_entity(worker_id, value)` — обновляет поле и
  `updated_at`.
- `bot/api_server.py`: `PUT /api/workers/<worker_id>/legal-entity`,
  тело `{"legal_entity": "..."}`, возврат `{"ok": true}`.
- `UI/src/api_client.py`: `set_legal_entity(worker_id, value) -> bool`.
- `UI/src/models.py`: поле `legal_entity`, `from_row()`, `to_dict()`.

### UI

- `UI/src/main.py`: в блоке личной информации строка «Юр. лицо: ...» и кнопка
  «Изменить».
- `UI/src/dialogs.py`: `LegalEntityDialog` — `Entry`, кнопки «Отмена»/«Сохранить»,
  центрирование, `grab_set`.
- После сохранения перечитать карточку и обновить строку в списке.
- `UI/src/services.py`: «Юр. лицо» в PDF-профиле.

Отдельный endpoint выбран специально: общий `update_worker()` не должен затирать
UI-only поля при повторной отправке анкеты из бота.

## Критерии приёмки

1. В карточке видно «Юр. лицо».
2. Пользователь может ввести и изменить значение через UI.
3. После перезапуска UI значение сохраняется.
4. Бот не спрашивает «Юр. лицо» и не показывает его в причинах отклонения.
5. Значение попадает в PDF-карточку.

## Тесты

- `docs_project/tests/test_db.py`: `set_legal_entity()` сохраняет значение и
  обновляет `updated_at`.
- `UI/tests/test_models.py`: `Worker.to_dict()` содержит `legal_entity`.

## Риски

- Поле не должно попадать в `db.save_worker()`: иначе бот обнулит его. Это
  зафиксировано в реализации.
