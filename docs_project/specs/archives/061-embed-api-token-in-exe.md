# Спецификация 061 — вшивка API-токена в собранный EXE

## Проблема
- UI работает как собранный `[Search]Driver.exe` на отдельных машинах кадров.
  Сейчас токен доступа к API (`API_TOKEN`) можно задать только вручную:
  переменная окружения или `.env` рядом с EXE. Для кадров это лишняя ручная
  операция с реальным шансом ошибиться: файл назван `.env.txt`, BOM в первой
  строке, кавычки вокруг значения, забытый перезапуск EXE — и UI получает 401.
- Токен сервера задаётся в `bot/.env` (в git не попадает). Машина сборки EXE
  должна получить его оттуда же или из переменной окружения, иначе вшивать
  нечего.

## Что изменить
- `UI/build_exe.py`: при сборке читает токен из переменной окружения
  `UI_BUILD_API_TOKEN`, затем `API_TOKEN`, затем из строки `API_TOKEN=` в
  `bot/.env` в корне проекта. Пишет сгенерированный модуль
  `UI/src/_api_secret.py`, который уезжает в бандл PyInstaller, и удаляет его
  сразу после сборки — в дереве исходников секрет не остаётся. Значение
  токена в лог сборки не выводится, только источник.
- `UI/src/config.py`: приоритет токена — переменная окружения → `.env` рядом
  с EXE → токен, вшитый в EXE → пусто. Чтение `.env` теперь снимает
  обрамляющие кавычки и BOM, как это делает `python-dotenv` на сервере:
  иначе значение в EXE и на сервере будут различаться на один символ.
- `.gitignore`: `UI/src/_api_secret.py` — секрет не попадает в git.

## Критерий приемки
- Собранный EXE на машине без дополнительных файлов работает с API, у которого
  задан `API_TOKEN`: запросы уходят с заголовком `X-API-Token`.
- Приоритет токенов соблюдается: переменная окружения > `.env` рядом с EXE >
  встроенный в EXE.
- После сборки `UI/src/_api_secret.py` отсутствует, в git секрет не попадает,
  значение токена не печатается в лог сборки.
- Тесты `python -m pytest -q` — зелёные.

## ponytail
Токен в EXE извлекаем — это ключ уровня сотрудника кадров, доступ к API для
тех, кому роздан EXE. Секретность даёт закрытый порт 56755, а не бинарник.
Обфускация токена не добавляет защиты и не делается.
