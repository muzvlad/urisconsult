# Спецификация 004 — валидация HR-даты + устаревший тест версии схемы

## Проблема
1. `db.set_hr_status` (`bot/services/db.py:899`) и `_valid_hr_date_local` принимают дату только `ДД.ММ.ГГГГ`. Тест передает ISO `2024-01-15` и ожидает `True` — получает `False`. API-валидатор `_valid_hr_date` (`api_server.py:63`) тоже требует `ДД.ММ.ГГГГ`. Нет единого формата между слоями.
2. Для статусов `employed`/`fired` не требуется непустая дата (тест `test_set_hr_status_requires_date` ожидает `False` при `None`, код возвращает `True`).
3. Тест `test_init_db_schema_version` ожидает `user_version == 6`, актуальная версия — 7.

## Что изменить
1. Унифицировать формат HR-даты (рекомендуется `ДД.ММ.ГГГГ` по всему стеку) и одинаково валидировать в `db.py`, `api_server.py`, тестах.
2. `set_hr_status`: для `employed`/`fired` требовать непустую валидную дату; для остальных — дата опциональна.
3. Обновить `test_init_db_schema_version` до версии 7.

## Критерий приемки
`set_hr_status("id","employed","2024-01-15")` → `True` (или конвертируется к единому формату); `set_hr_status("id","employed",None)` → `False`; версия схемы в тесте == 7.

## ponytail
Не менять формат хранения в БД (оставить TEXT), только привести валидацию к общему знаменателю.
