# Спека 010 — Комментарий к каждому документу при отклонении анкеты

## Проблема

Сейчас при отклонении анкеты в UI специалист выбирает только поля/документы (чекбоксы) —
комментарий написать нельзя. Клиент получает в Telegram лишь список названий документов:

> Необходимо исправить:
>   - ИНН
>   - Паспорт

Нет возможности объяснить клиенту, **что именно** исправить в каждом документе.

## Требование

1. В UI при отклонении анкеты для **каждого** выбранного документа можно ввести свой комментарий.
2. Комментарий приходит клиенту через бота (в уведомлении и при исправлении).
3. Комментарий сохраняется в БД вместе с причинами.

## Решение

### 1. Формат причин

`rejection_reasons` (JSON в колонке `workers.rejection_reasons`) меняется со списка строк
на список объектов:

```json
[{"key": "patent_inn", "comment": "Номер не читается, сделайте чёткое фото"}]
```

Для обратной совместимости все парсеры принимают и старый формат (строку `"patent_inn"` →
`{"key": "patent_inn", "comment": ""}`).

### 2. UI — диалог отклонения (`UI/src/dialogs.py`, `RejectDialog`)

- Рядом с каждым чекбоксом — поле ввода комментария (`tk.Entry`), активное только когда
  чекбокс отмечен.
- `do_reject()` собирает `[{"key": key, "comment": comment}, ...]` для отмеченных полей.
- `RejectDialog.on_confirm` и `_handle_reject` принимают новый формат.

### 3. UI — отображение и отправка

- `UI/src/models.py` `Worker.reasons` — парсер: возвращает список dict'ов; поддерживает старый
  формат (строка → `{"key": ..., "comment": ""}`).
- `UI/src/main.py:710` — показ замечаний в карточке: комментарий отдельной строкой под названием.
- `UI/src/services.py` `_send_rejection_sync` — текст уведомления включает комментарий:
  `  - ИНН\n    Комментарий: ...`.
- `UI/src/services.py` PDF-экспорт — комментарий под названием документа.
- `UI/src/api_client.py` `reject_worker` — тип `List[Dict]`.

### 4. Бот

- `bot/services/db.py` `reject_worker` — принимает список dict'ов (или строк, для совместимости).
- `bot/handlers/commands.py`:
  - парсер `rejection_reasons` (учитывает оба формата),
  - `handle_rejected_callback` / `_ask_rejected_field` — запрашивает исправление и показывает
    комментарий (`_ask_rejected_field` должен принять `{"key", "comment"}`).
  - `process_fix_value` / документный fix — переход по полям `key`.
- `bot/bot.py:178` — уведомление: показывать комментарий после названия поля.
- `bot/api_server.py` `reject_worker` — прокидывает причины как есть.

### 5. Совместимость fix-потока

`_ask_rejected_field(message, state, field, reasons, index)` сейчас принимает `field` (строку) и
`reasons` (список). При новом формате `reasons` = список dict'ов, `reasons[index]` = dict.
Адаптировать: `field = reasons[index]['key']`, `comment = reasons[index]['comment']`. Показывать
комментарий в запросе. `_download_document`/`_skip_document` обращаются к `fix_reasons[index]` для
перехода к следующему — обновить под dict-формат (или передавать отдельный список ключей).

## Критерии приёмки

1. В диалоге отклонения для каждого отмеченного документа можно ввести комментарий.
2. Клиент получает комментарий в уведомлении и при исправлении документа.
3. Комментарии сохраняются в БД и видны в UI (карточка анкеты, PDF).
4. Старые анкеты со строками-причинами работают (обратная совместимость).
5. `pytest docs_project/tests/ UI/tests/` зелёный.
