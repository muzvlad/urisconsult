# Спецификация 001 — убрать дублирование уведомлений об отказе

## Проблема
При отклонении анкеты из UI (`UI/src/services.py:204`, `TelegramService.send_rejection`) бот шлет уведомление в Telegram сразу. `db.reject_worker` (`bot/services/db.py:834`) обнуляет `notified_at = NULL`. Фоновая задача `check_rejected_workers` (`bot/bot.py:158`) каждые 60 с берет всех `rejected` с пустым `notified_at` и шлет то же уведомление снова, потом ставит `notified_at`. Пользователь получает одно и то же уведомление дважды.

## Что изменить
Выбрать одну точку отправки. Рекомендация: убирать отправку из UI (`TelegramService.send_rejection` не шлет сообщение, только ставит статус), фоновая задача бота остается единственным отправителем и ставит `notified_at` после успешной отправки. Если UI хочет подтвердить отправку — он вызывает API, которое ставит `notified_at` само.

## Критерий приемки
При отклонении из UI пользователь получает ровно одно уведомление в Telegram; повторных отправок за те же причины нет.

## ponytail
Не вводить новую таблицу или флаг — использовать существующее поле `notified_at`.
