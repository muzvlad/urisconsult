# Спека 025 — HR-статус

## Проблема

В карточке есть только статус анкеты в боте (`pending/accepted/rejected`). Он не
отражает кадровый процесс, и менять его из UI нельзя.

## Решение

Отдельный HR-статус, не связанный с ботом. Бот не показывает и не меняет его.

### Статусы

| Ключ | Подпись |
|------|---------|
| `not_processed` | Новый |
| `docs_pending` | Ожидает документы |
| `employed` | Трудоустроен |
| `rejected` | Отказ |
| `fired` | Уволен |

Новые анкеты получают `not_processed`. Старые записи с `NULL` отображаются как
`not_processed`.

### БД и API

- Колонки `workers.hr_status TEXT`, `workers.hr_status_date TEXT` добавляются
  миграцией v6 (спека 021).
- Миграция заполняет существующие строки значением `not_processed`.
- `bot/services/db.py`: `set_hr_status(worker_id, status, date_value) -> bool`.
  Проверка допустимых ключей на уровне функции.
- `bot/api_server.py`: `PUT /api/workers/<worker_id>/hr-status`,
  тело `{"hr_status": "...", "hr_status_date": "дд.мм.гггг"}`.
  - Неизвестный статус — 400.
  - Дата обязательна для `employed` и `fired`.
  - Для остальных статусов дата очищается.
  - Неверная дата — 400.
- `UI/src/api_client.py`: `set_hr_status(worker_id, status, date_value) -> bool`.
- `UI/src/models.py`: поля `hr_status`, `hr_status_date`, `from_row()`, `to_dict()`.

### UI

- `UI/src/config.py`: `HR_STATUS_LABELS`, `HR_STATUS_KEYS`.
- `UI/src/main.py`: блок «HR-статус» в карточке:
  - `ttk.Combobox` со статусами;
  - поле даты `дд.мм.гггг` (активно только для «Трудоустроен»/«Уволен»);
  - кнопка «Сохранить».
- Список: существующая колонка «Статус» переименовывается в «Статус бота»,
  добавляется колонка «HR-статус».
- В карточке бот-статус и HR-статус подписаны раздельно, чтобы их не путали.
- После сохранения обновить карточку и строку списка.

Бот при `accepted` не должен автоматически ставить `employed` — это ручное решение
кадровика.

## Критерии приёмки

1. HR-статус отображается в карточке и списке отдельно от статуса бота.
2. Статус меняется из UI и сохраняется.
3. Для «Трудоустроен» и «Уволен» дата обязательна.
4. При смене на другой статус дата очищается.
5. Бот не меняет HR-статус.
6. Неизвестный статус или неверная дата не сохраняются.

## Тесты

- `docs_project/tests/test_db.py`: `set_hr_status()` сохраняет статус и дату,
  отклоняет неизвестный ключ.
- `docs_project/tests/test_api.py`: 400 на неверный статус и отсутствие даты для
  `employed`; успешное обновление.
- `UI/tests/test_models.py`: поля HR-статуса в `Worker.to_dict()`.

## Риски

- Дублирование смысла «Отказ» с бот-статусом `rejected` допустимо: это разные
  процессы. В интерфейсе они подписаны раздельно.
