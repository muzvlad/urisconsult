# Спека 019 — API-сервер: многопоточный режим (не блокирует весь API при зависшем запросе)

## Проблема

Flask API-сервер бота запускается как `app.run(...)` **без `threaded=True`**. Werkzeug по
умолчанию обслуживает один запрос за раз. Если один запрос блокируется (например, чтение файла
документа с сетевой шары `NETWORK_SERVER`, которая временно недоступна), весь API перестаёт
отвечать — UI не получает ни метаданные, ни файлы, загрузка документов «пропадает».

Симптом на проде: `/api/workers` и `/api/workers/{id}/documents` отвечают быстро, но
`/docs/{worker_id}/{filename}` зависает, после чего перестаёт отвечать и всё остальное.

## Решение

Включить `threaded=True` в запусках Flask API-сервера:

1. `bot/bot.py` `_start_api_server` — `app.run(host='0.0.0.0', port=API_PORT, debug=False,
   use_reloader=False, threaded=True)`.
2. `bot/api_server.py` `__main__` — `app.run(host='0.0.0.0', port=8080, debug=False, threaded=True)`
   (для локальной отладки).

Зависший запрос будет занимать один поток и не блокировать остальные. БД — WAL +
`busy_timeout=30000`, соединения короткоживущие, конкурентный доступ безопасен.

Операционная причина зависания (недоступная сетевая шара DOCS_DIR) — вне кода, решается
проверкой `NETWORK_SERVER` на сервере.

## Критерии приёмки

1. Один медленный/зависший запрос `/docs/...` не блокирует `/api/workers`.
2. `pytest docs_project/tests/ UI/tests/` зелёный.
