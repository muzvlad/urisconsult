# Спека 002 — Новый порядок анкеты (патент) + общий порядок личных полей

## Проблема

Текущий порядок анкеты не совпадает с бизнес-процессом:

- Личные поля бота (`bot/handlers/registration.py`) идут в порядке:
  ФИО → категория → пол → **должность → объект → адрес → менеджер → тел. → доп. тел. → дата рождения** → документы.
  Нужен порядок: ФИО → категория → пол → **дата рождения → менеджер → объект → адрес → должность → тел. → доп. тел.** → документы.
- Патентный поток документов (`bot/config/documents.py` `DOC_FLOWS['Патент']`) идёт в другом порядке, чем требуется.
- «Регистрация» — одно фото, а по ТЗ нужны два слота (лицевая + оборотка) с возможностью скрина из приложения «Амина».
- Чеков по патенту 3, а по ТЗ может быть до 11.

## Решение

### 1. Личные поля — новый порядок (общий для всех категорий)

Порядок запроса в боте:
1. ФИО
2. Категория (инлайн-кнопки)
3. Пол (кнопки Мужской/Женский)
4. Дата рождения (ДД.ММ.ГГГГ)
5. Имя менеджера
6. Объект
7. Адрес объекта
8. Должность
9. Основной телефон
10. Доп. телефон (или «Пропустить»)

Затем — документы по категории.

Текстовые поля общие для всех категорий, поэтому порядок меняется глобально.
Email в потоке отсутствует (как и сейчас) — поле остаётся в FSM, но не запрашивается.

### 2. Документы патента — новый порядок и новые типы

Новый поток `DOC_FLOWS['Патент']`:

1. Фото (селфи) `photo`
2. Паспорт (разворот) `passport`
3. Перевод паспорта `patent_passport_translation`
4. Миграционная карта `patent_migration_card`
5. Регистрация (лицевая) / скрин Амина `patent_registration` — префикс `reg` (сохранён, старые файлы не ломаются)
6. Регистрация (оборотная) `patent_registration_back` — **новый**, префикс `reg_back`, пропускаемый
7. Дактилоскопия (лицевая) `patent_fingerprint_front`
8. Дактилоскопия (разворот) `patent_fingerprint_back`
9. Полис ДМС `patent_dms`
10. Патент (лицевая) `patent_patent_front`
11. Патент (разворот) `patent_patent_back`
12. Чек 1..11 `patent_receipt_1` … `patent_receipt_11` — префиксы `chek1`…`chek11`, каждый пропускаемый. Чек 4..11 — **новые**.
13. Сертификат о знании языка `patent_language_cert`
14. ИНН `patent_inn`
15. СНИЛС `patent_snils`
16. Банковские реквизиты `patent_bank_details`

Итого 26 документов (было 17).

### 3. Обработка «Регистрация или скрин Амина»

- Слот «лицевая»: просим «регистрацию (лицевая сторона) **или** скрин из приложения Амина».
- Слот «оборотная»: пропускаемый — для скрина Амина (одно фото) либо если оборотки нет.

### 4. UI

Порядок документов и их названия в UI подтягиваются автоматически из `bot/config/documents.py`
(`get_document_config()`): список документов в карточке, PDF-экспорт, чекбоксы отклонения — новый порядок и новые типы.

Вручную обновить порядок личных полей:
- `UI/src/main.py` — блок «Личная информация» (гражданство, пол, дата, менеджер, объект, адрес, должность, телефон, доп. телефон).
- `UI/src/dialogs.py` — `RejectDialog` и `EditDialog` списки базовых полей.
- `UI/src/services.py` — `PDFExportService` список профильных полей.
- `UI/src/database.py` — fallback-маппинг префиксов (добавить `reg_back`, `chek4`…`chek11`).

### 5. Экран подтверждения и редактирование в боте

- `bot/handlers/confirmation.py` — порядок личных полей на экране подтверждения.
- `bot/utils.py` — `_BASE_FIELDS` (клавиатура редактирования) в новом порядке.
- `bot/handlers/commands.py` — списки полей при исправлении отклонённой анкеты.

### 6. Build EXE

`UI/build_exe.py` уже вшивает `bot/config/` (documents.py) и `shared/` в бандл —
для актуализации exe достаточно пересобрать (`UI/build_exe.bat` / `build_exe.py`).
Изменения в самом билд-скрипте не требуются (новые типы документов — это данные конфига, не новые файлы/зависимости).

## Что НЕ делаем

- Не меняем схему БД (`worker_documents` хранит `doc_type` строкой — новые ключи подходят без миграций).
- Не трогаем остальные категории (Студент/ЕАЭС/РВП/ВНЖ/Россия) — их потоки документов остаются как есть.
- Не меняем `api_server.py` / `api_client.py`.
- Email не возвращаем в анкету.

## Проверка

1. Бот: `cd bot && python -m pytest` — тесты бота (обновить патентный счётчик 17 → 26).
2. Документация: `cd docs_project && python -m pytest tests/test_config_documents.py` и `tests/test_handlers.py`.
3. UI: `cd UI && python -m pytest` — тесты UI.
4. Вручную: регистрация патентника — порядок 1–10 (личные поля) и 11–25 (документы) совпадает с ТЗ;
   для «Регистрации» просят два слота, скрин Амина — один (оборотка пропускается);
   чеки до 11, каждый можно пропустить.
5. Пересобрать exe и убедиться, что новые документы/порядок отображаются в карточке, PDF и окне отклонения.
