### Миниатюры PDF в UI
- Для PDF-документов вместо кнопки «открыть» теперь рендерится миниатюра первой страницы через PyMuPDF (`fitz`), клик открывает файл как у изображений

- Добавлены тесты `test_load_pdf_thumbnail` и `test_load_pdf_thumbnail_invalid`

### Резервирование ID без лишних `__reserved__`
- `db_saver.py:save_worker_data()` использовал `data.get('id', await db.get_next_id())` — аргумент по умолчанию в `dict.get()` вычисляется сразу, поэтому `get_next_id()` (создающий `__reserved__`) вызывался при каждом сохранении, даже когда `id` уже есть. Резервы плодились впустую при исправлениях/переподачах. Заменено на явную проверку `if data.get('id')`
- Добавлен тест `test_save_worker_with_existing_id_no_extra_reserved`

### Фильтрация `__reserved__` из списка анкет
- `get_all_workers()` и `search_workers()` не фильтровали заглушки `__reserved__` (создаются `get_next_id()` при резервировании ID во время регистрации). Сирота от прерванной регистрации показывался в общем списке анкет в UI. Добавлен фильтр `name != '__reserved__'` в оба запроса
- `__reserved__` резервируется корректно — только для пользователя, начавшего регистрацию (с ввода ФИО), и при старте бота сироты чистятся
- Добавлен тест `test_reserved_not_in_list`

### Документы в разных форматах
- Бот принимает не только jpg, но и все виды изображений (png, jpeg, bmp, gif) и PDF (форматы уже были в `ALLOWED_EXTENSIONS`)
- Имена файлов строятся одинаково для всех форматов: `{prefix}.{ext}` — тот же префикс, что у jpg, отличается только расширение (например `pas.jpg` -> `pas.pdf`)
- UI ищет документ также среди `.pdf` — `DocumentService._find_document_file()` теперь перебирает `image_extensions + ['.pdf']` вместо только изображений, чтобы PDF находился при экспорте и по префиксу
- `DocumentViewer` для не-изображений (PDF и др.) показывает вместо миниатюры кликабельную кнопку «открыть» — файл открывается системным просмотрщиком
- Нюанс Telegram: картинку, отправленную как фото, Telegram сам сжимает в jpg. Чтобы сохранить PNG/PDF как есть, файл нужно отправлять как документ (скрепка)

## v1.13 (30.07.2026)

Глубокий аудит проекта: 15 исправлений багов, уязвимостей и code smell. 106/106 тестов.

### Критические исправления
- **`updated_at` отсутствовал в схеме БД** — `shared/__init__.py` и `db.py:init_db()` не содержали колонку `updated_at`, хотя `save_worker()` и `db_saver.py` её записывали. На свежей БД первый `save_worker` падал с `OperationalError`
- **`created_at` перезаписывался при обновлении** — `save_worker()` использовал `ON CONFLICT DO UPDATE SET created_at = excluded.created_at`, затирая дату создания. Исключён из UPDATE-клауза
- **Race condition в `get_next_id()`** — TOCTOU: два параллельных запроса читали одинаковый max ID, `INSERT OR IGNORE` молча проглатывал второй. Заменён на retry-цикл с `IntegrityError`
- **Edit keyboard показывал документы** — при редактировании анкеты кнопки включали 📎-поля документов, которые нельзя изменить текстом. Теперь только текстовые поля

### Серьёзные исправления
- **Миграция v0→v1 дублировала документы** — документы копировались дважды: из оригинальной и переименованной таблицы. Убрано первое копирование
- **`commit` вне контекстного менеджера** — `UI/src/database.py:_sync_docs_from_disk()` имел `conn.commit()` после `with`-блока (мёртвый код)
- **Фильтрация по статусу в Python** — `api_server.py` загружал ВСЕХ работников и фильтровал в Python. Добавлена SQL-функция `get_workers_by_status()` с WHERE
- **Отсутствовал эндпоинт `resubmit`** — UI не мог запустить повторную подачу через API. Добавлен `PUT /api/workers/<id>/resubmit`

### Очистка кода
- Удалён мёртвый `_RUSSIA_PROPISKA` (определён, но не использовался)
- Удалено неиспользуемое FSM-состояние `russia_relatives_phone`
- Убран redundant import внутри `_ask_rejected_field`
- Добавлена документация: семейное положение запрашивается только для мужчин (осознанно)
- API ошибки логируются, клиенту возвращается generic "Internal error"
- Миграции сделаны атомарными (убран промежуточный `commit`)
- Очистка `__reserved__` записей-сирот при старте бота

### Тесты
- Обновлены тесты под актуальный код (106 тестов):
  - `test_patent_has_12_docs` → `test_patent_has_17_docs`
  - Regex `[a-z_]+` → `[a-z0-9_]+` (патент Receipt ключи с цифрами)
